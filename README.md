# 电网业务研习室

一套面向软件研发人员的国家电网业务知识静态学习应用。当前已提供 32 讲完整课程、平台及专业微应用业务地图、真实设备照片和随堂测验；不需要登录、数据库或后端服务。

课程以业务理解为主线。第 09～19 讲按完整业务模块讲解现场作业平台，覆盖工单计划、现场勘察、人员责任田、班前会、工作票、现场执行、异常、监督、安全知识、标准作业、生产要素、分级管控、五维评价和统计分析；第 20～29 讲完整讲解设备主人、计量箱建档、一键装拆、巡视核抄、空间拓扑、采集异常、缺陷整改、离线作业和计量追溯等专业微应用。读者读完全部章节后，应能复述平台实现了哪些业务、模块如何衔接，而无需逐页阅读代码。拓扑和接线使用本地 SVG 教学插图，设备科普使用本地化的真实照片，不依赖外部图片服务。

## 学习规则

- 首次打开默认进入第01讲。
- 侧边栏“完整学习路线”展示四阶段 32 讲的知识网络。
- 每讲均提供目标、业务背景、核心概念、对象关系、流程、案例、研发理解、总结和3道测验。
- 一章的测验答对至少 2 题后，记为完成。
- 完成记录不会限制任何章节的访问顺序。
- 进度保存在当前浏览器的 `localStorage`，键名为 `sgcc-grid-learning-progress-v1`。
- 更换浏览器、设备或清理站点数据不会自动迁移进度。

## 本地预览

在应用目录运行：

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080/`。

## 服务器部署

将 `grid-learning` 目录中的全部文件复制到 Nginx、Apache、对象存储或其他静态站点目录即可。入口为 `index.html`，所有资源均使用相对路径，不需要额外配置接口或反向代理。

不建议直接双击 `index.html` 使用 `file://` 打开；通过 HTTP/HTTPS 部署可以避免不同浏览器对本地文件与 `localStorage` 的限制。

## GitHub Pages

仓库通过 `.github/workflows/deploy-pages.yml` 发布静态站点。推送 `main` 分支或在 Actions 中手动运行 `Deploy GitHub Pages` 后，站点发布到：

https://blues-web.github.io/grid-business-learning/

## 内容维护

- 章节、案例和测验位于 `assets/content.js`。
- 完成判定、顺序推进和章节选择位于 `assets/progress.js`。
- 页面交互位于 `assets/app.js`。
- 视觉样式位于 `assets/styles.css`。
- 完整学习路线位于 `assets/roadmap.js`，阶段顺序为“基础电力业务 → 现场作业平台 → 现场专业应用 → 端到端综合实战”。
- 平台与微应用完整业务模块清单位于 `assets/business-maps.js`，按对应章节合并到正文。
- 教学插图位于 `assets/images/`。
- 真实设备照片位于 `assets/images/real/`，来源和许可见同目录 `CREDITS.md`。

新增章节时，在 `chapters` 数组末尾添加结构相同的章节对象，并更新新增章节的 `next` 字段即可。课程总数和进度会自动按数组长度计算。

### 内容编写约定

- 专业术语首次出现时，要先用通俗语言说明“是什么”，再给常见现场例子。
- 容易混淆的词要明确对照，例如供电点、计量点、公变、专变、缺陷、故障。
- 解释业务状态时，要说明谁会使用这个结果，以及判断错误会影响客户、计量、运检还是后续作业。
- 数字和参数要带单位，并说明它是额定值、实时值、累计值还是业务上限。
- 涉及省公司差异、现场制度和分类口径时，明确提示需要核实，不写成全国统一规则。
- 正文以业务理解为主，不用数据库结构、接口 JSON 或技术实现替代业务解释。
- 平台模块按业务能力组织，不把新旧版本、省侧副本和纯详情页重复计算为不同业务。
- 每个平台章节要说明模块目的、角色、对象、流程和上下游；每个微应用章节要说明平台下发、现场动作、结果回传和档案更新。
